# Demonstration and handover scripts

## Before recording

Use fictional customers and a development provider account. Verify database migrations, indexed knowledge, worker heartbeat, the actual n8n agent and at least one live channel. Hide credentials and notifications. A recording must not substitute mock messages for live ones without an explicit label.

## Coding challenge: 2–3 minutes

**00:00–00:20 — Context.** Show the selected Upwork posting and say this is an implementation of its n8n business-automation requirements, using the fictional Nexa business.

**00:20–00:45 — Conversation.** Send a company-services question through a genuinely connected channel. Show the real response and its knowledge source. State which channel/account is connected.

**00:45–01:20 — Action.** Provide a fictional name/business need, let the agent qualify the lead, and show the new CRM record. Ask for an available appointment and explicitly confirm its date/time/timezone. Show the persisted booking.

**01:20–01:50 — Human control.** Ask for a human, show the handoff in Unified Inbox, and send an operator reply through the original channel. Demonstrate that AI handling is paused.

**01:50–02:15 — Evidence.** Show the n8n execution ID, application execution record and relevant test report. Distinguish sent/accepted from delivered/read where the provider supports receipts.

**02:15–02:50 — Comparison.** Compare the three independent coding runs using observed access, cost, time, failed requests and completed acceptance tests. Disclose account approvals/credentials still missing. Recommend from measurements, not brand preference.

A build created through this GitHub-assisted conversation is not automatically evidence that Cline, OpenCode or Codex independently built it. Record external assistance and do not reuse generated source across tools while describing the results as independent.

## Client handover: 15–20 minute outline

1. Business objectives and implemented versus excluded scope.
2. Native Windows installation, runtime keys and configuration ownership.
3. Database schema, migration process, backups and restore responsibilities.
4. n8n workflow graph, credential binding, model selection and publishing.
5. Customer journey with evidence for knowledge, CRM, booking and handoff.
6. Telegram, Slack and WhatsApp account setup and channel-specific constraints.
7. Email triage, document extraction, review and export.
8. Follow-up consent/deduplication, retries, uncertain delivery and error alerts.
9. Prompt editing, tests, operational limits and production-hardening checklist.
10. Known limitations and separately agreed support arrangements.

This is a recording script, not a claim that a video has already been recorded or that 14 days of future support has been contracted.
