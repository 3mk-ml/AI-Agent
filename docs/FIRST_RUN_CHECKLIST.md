# First run: your Windows checklist

This guide is for the GitHub implementation in `3mk-ml/AI-Agent`, not the separate project previously generated by another coding agent.

## Protect the existing work

Use a **separate Supabase development project/database** for this fresh implementation. Do not apply these migrations over an earlier Codex implementation merely because both use a schema named `agentflow`; their table definitions may differ. Keep your earlier source and database intact for the challenge comparison.

Stop the previous development server using port 3000 before opening this version. Do not terminate every Node.js process: one may be your still-running n8n installer. Run only one n8n installer at a time and preserve npm's cache.

## Open the application

From PowerShell, with Node.js 24 LTS and Git available:

```powershell
git clone https://github.com/3mk-ml/AI-Agent.git
cd AI-Agent
npm install --prefer-offline --no-audit --no-fund
npm run setup
npm run dev
```

For an existing clean clone, update it with `git pull --ff-only` rather than cloning into the same directory. Do not overwrite uncommitted local changes.

The setup command prints a local one-time token. Open `http://127.0.0.1:3000/login`, use that token, and create your administrator password. The dashboard can open before n8n is installed. Database-backed views will report the missing connection until the next step.

## Connect storage and AI

In **Connections**, enter the fresh Supabase PostgreSQL **session-pooler** URL, save, and apply migrations. Run diagnostics. Configure the provider's CA certificate when required; never disable remote TLS verification.

Save your Gemini API key, a chat model available to your account and a compatible embedding model. Saved secrets are encrypted locally; they are not sent to GitHub. Do not paste them into an issue or shared chat.

## Start the actual workflow engine

After your n8n installation completes, use `scripts/n8n.ps1 -Action status` and `-Action start`. The start action binds the editor to loopback and reuses the existing installation. Follow [N8N_SETUP.md](N8N_SETUP.md) for the exact credential/header mapping, draft import and workflow publication.

Keep the production webhook URL in AgentFlow settings, not n8n's temporary test URL. The webhook secret and tool secret are different values.

In another terminal in this repository, run:

```powershell
npm run worker
```

Add the fictional handbook under **Knowledge** and wait for the document to reach `ready`. This step performs real embedding calls and consumes your provider quota.

## Verify one complete customer journey

Open `/chat`. Ask about services, supply a fictional lead, request a future appointment, explicitly confirm the time, and request a human. Check the CRM, appointments, inbox and corresponding n8n execution. A queued message or configured credential is not a successful end-to-end test.

Then connect Telegram, Slack and WhatsApp one at a time using their setup guides. Test both inbound and outbound messages and human takeover on each. WhatsApp requires the official Meta account setup and public HTTPS ingress; only tunnel port 3001, never the dashboard or n8n editor.

The automated verification record is in [TEST_RESULTS.md](TEST_RESULTS.md). Live Gemini/n8n/provider tests still require your own accounts and must be recorded honestly for the challenge.
